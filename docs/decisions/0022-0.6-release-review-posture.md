# ADR 0022 - Maintainer acceptance is sufficient for the 0.6 release

**Status:** Accepted - 2026-07-11

## Context

The SSTIM improvement plan originally made one named, independent human
ontology review a release gate for `0.6.0`. No independent reviewer completed
that review before the planned release date.

The release was nevertheless reviewed directly by the maintainer throughout
development. That review guided the vocabulary and ontology changes, their
scope, and the dispositions from an external automated assessment. The six
modules also passed OOPS and FOOPS assessment, authoritative identifier and
safety-source checks, SHACL validation, ROBOT/HermiT consistency reasoning,
repository quality audits, competency queries, and serialization-isomorphism
checks.

An unavailable independent reviewer is a project-governance constraint, not an
ontology defect. Treating it as an indefinite blocker would also conflate
independent sign-off with the maintainer accountability that the project
already has.

## Decision

Renato Fabbri accepts SSTIM `0.6.0` for release after maintainer-guided review
and the automated validation recorded in the repository. An independent named
human ontology review is desirable but is not a prerequisite for `0.6.0`; it is
deferred until a suitable reviewer is available, potentially for `0.7.0` or a
later release.

Release and publication material must state the review posture precisely. It
may claim maintainer-guided review and the named automated checks, but it must
not claim independent human sign-off.

The semantic release still requires synchronized release metadata, a core
`owl:versionIRI`, a validated immutable snapshot, a Git tag, and a Zenodo
version record. WIDOCO documentation and public-registry submissions remain
post-release FAIR-publication work rather than blockers for the versioned RDF
artifact.

## Alternatives considered

- **Wait indefinitely for an independent reviewer.** Rejected: no semantic or
  validation finding remains that justifies withholding the reviewed artifact.
- **Describe the automated assessment as human review.** Rejected: this would
  misstate the provenance and independence of the review.
- **Remove independent review from the roadmap.** Rejected: outside review is
  still valuable for later model and evidence development.

## Consequences

- `0.6.0` can be released with an auditable and accurately described review
  record.
- Consumers can distinguish maintainer acceptance from independent external
  human sign-off.
- A later human review may produce changes for `0.7.0` or beyond without
  retroactively invalidating the immutable `0.6.0` snapshot.
- Registry and generated-documentation work can proceed against a stable
  release instead of a moving development line.
