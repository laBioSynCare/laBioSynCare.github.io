# ADR 0027 migration ledger

**Status:** Normative annex to Proposed ADR 0027 — 2026-07-13

This ledger fixes the disposition of every live node currently typed
`sstim:EvidenceClaim`. It is the normative annex to
[ADR 0027](../decisions/0027-evidence-claim-family-and-public-claim-gate.md),
not an implementation record. Protected RDF sources remain unchanged until the
ADR is accepted. Once ADR 0027 is accepted, changing any disposition in this
ledger requires an amendment to that ADR. A disposition is the retain/retire
decision, target role, initial basis, or bounded proposition/scope—not a
scientific tier or direction assigned by an assessment activity. Later evidence
or rubric changes create ordinary immutable assessment revisions and do not
amend this migration ledger.

The inventory covers 38 nodes: 11 assessment candidates and 27 experiment
pseudo-claims. Frozen `static/ontology/<version>/` snapshots are immutable and
are not migrated.

## Assessment candidates

Each retained candidate is a legacy source record, not an immutable assessment
revision. Migration mints a new IRI by appending `/revision/1` to its existing
slash IRI. The new node is explicitly typed
`sstim:EvidenceAssessmentClaim, sstim:EvidenceClaim`, uses
`sstim:evaluatesSubject`, assesses one atomic bounded proposition with an
explicit outcome/scope, and has a qualified evidence basis. It is generated by
a migration-dated assessment activity and is `prov:wasDerivedFrom` the legacy
node. The old IRI becomes a deprecated tombstone linked to the new revision.
The compatibility superclass and deprecated subject property are dual-
published on the new revision only as specified by ADR 0027.

Migration records what is done now; it must not invent a historical activity,
rubric, search, decision, date, reviewer relationship, or independence claim.
The migration assessment uses the actual migration method revision and an
honest qualified agent/role association. A separate review decision is created
only when its source provenance can be demonstrated; any reviewer relationship
is then recorded as self, same organization, external, or unknown rather than
inferred from a label.

### Authoritative basis metadata

Legacy `hasModalityTag` values are migration clues, never authoritative source
metadata. Each qualified basis is classified from the cited source itself, and
legacy assessment summaries map, only after source verification, to
`basisStudyPopulation`, `basisComparator`, `basisObservedOutcome`, and
`basisObservedEffectDirection`. They do not define the assessment proposition
or its scope. The migration must distinguish the narrower conclusion assessed
from the populations, comparators, outcomes, and directions reported by each
source. Existing population/outcome/comparator literals become supplementary
notes only after the migration mints or reuses the corresponding descriptor or
outcome IRIs; a literal never substitutes for the object-property value.
Source publication dates remain `dct:issued` on the bibliographic reference;
assessment and review dates come from their own activities.

### Assessment propositions and scopes

For each revision, mint `{revision-iri}/proposition` and
`{revision-iri}/scope`. Outcome IRIs use the existing BSC evidence namespace
with the `outcome/` suffixes below. These are the bounded propositions the
bases assess; basis-level reported results remain separate. The migration
activity assigns and justifies direction/tier under its actual method rather
than pretending that the legacy editorial label was an earlier rubric. Ratings
shown below are non-normative legacy inputs that must be reassessed; this ADR
does not approve them.

The table uses the existing namespaces `sstim-v:`
(`https://w3id.org/sstim/vocab#`), `bsc-fw-tech:`
(`https://w3id.org/sstim/framework/bsc/technique/`), and `bsclab-preset:`
(`https://w3id.org/sstim/implementation/bsclab/preset/`).

migration may assign a different value under the adopted rubric, and later
evidence or rubric changes mint a new assessment revision without changing this
annex.

The generated 0.7 compatibility view may emit the following legacy tags only
from the corresponding explicit authoritative facts:

| Legacy tag | Lossless source condition |
|---|---|
| `AUD` | basis explicitly identifies auditory modality |
| `VIS` | basis explicitly identifies visual modality |
| `TACTILE` | basis explicitly identifies somatosensory/tactile delivery |
| `AV` | basis explicitly identifies combined auditory and visual delivery, not merely a mixed review |
| `BREATH` | `basisIntervention` explicitly identifies paced breathing |
| `PRECLINICAL` | basis explicitly identifies a preclinical model/stage |
| `REVIEW` | basis explicitly identifies a systematic review or meta-analysis, matching the legacy value's definition |
| `MULTISENSORY` | basis explicitly identifies combined multiple-modality applicability and the supported canonical modalities |

`GENERAL` has no lossless reverse mapping because mixed, unknown/not reported,
and not applicable are distinct. Narrative reviews and tutorials do not acquire
the narrower legacy `REVIEW` value merely because they synthesize literature.

### Scoped-status replacements and duplicate prose

Each of the three `KnowledgeStatusAssertion` replacements is linked from its
technique with `hasKnowledgeStatusAssertion`, carries exactly one
`hasKnowledgeStatus` value, an explicit repository/corpus IRI through
`knowledgeScope` or language note through `knowledgeScopeNote`, and an as-of
date.
It is generated by a migration-dated `KnowledgeStatusActivity` with the actual
method/corpus revision and a qualified responsible agent/role; no historical
search or review is implied.
Its replacement IRI appends `/status/1` to the existing slash IRI; the legacy
claim IRI becomes a deprecated tombstone linked to that record.
The color-field, reference-pitch, and Solfeggio `editorialNote`, `scopeNote`, or
`evidenceNotes` text that currently repeats a universal/refuting judgment must
be replaced with neutral text pointing to the scoped status assertion. The
broader outcome-prose cleanup remains KR-08; this migration must at least avoid
preserving the three retired assertions in ungoverned annotations.

## Cross-cutting migration rules

For all 27 experiment nodes:

- remove `sstim:EvidenceClaim` and `sstim-ex:ExposureEffectClaim` typing;
- remove evidence tier, evidence modality, claim direction, review status,
  `evidenceDate`, and other evidence-assessment-only metadata;
- preserve useful labels, descriptions, and attribution where they remain
  accurate;
- advance `dct:modified` to the migration date on every in-place artifact whose
  type, description, status, or links change; preserve the prior date in the
  migration activity/history or frozen snapshot, not as the artifact's current
  modification date;
- replace every `hasEffectClaim` link with its role-specific link;
- preserve already-structured boundary, capability, gain/loss, context, and
  role-valid knowledge-status facts rather than duplicating them in prose;
- remove or replace any knowledge-status value whose meaning contradicts the
  target role, including the four row-specific dispositions above; and
- change or remove the `concernsEffectDimension` OWL domain before reusing the
  property, so it cannot infer the deprecated class.

For new assessment revisions, the legacy `dct:modified` remains historical in
the frozen source snapshot or explicit migration provenance. If the active
legacy IRI becomes a tombstone with new deprecation/replacement links, its
current `dct:modified` advances to the migration date as well. A new revision
may receive its migration creation date as `dct:modified`, but that value then
freezes; every later content change mints another revision IRI.

Validation must reconcile the new counts, loader/browser queries, golden
runtime fixture, documentation, and frozen-snapshot exclusions in the same
0.7 release boundary.
