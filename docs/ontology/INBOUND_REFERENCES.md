# Inbound references: getting the outside world to point at SSTIM

**Status:** active plan, created 2026-09-05. Maintainer: Renato Fabbri.

Every external mapping this project publishes points **outward**: SSTIM makes a
claim about someone else's identifier. This document owns the other direction,
which nothing else here tracks: records, items and datasets **outside** SSTIM
that reference an SSTIM IRI, DOI or namespace.

The two are not interchangeable. An outbound mapping helps somebody who already
has SSTIM in hand. An inbound reference is what lets a reader on `alpha wave`, or
a reconciliation tool holding a MeSH descriptor, arrive here at all.

[REGISTRY_SUBMISSIONS.md](REGISTRY_SUBMISSIONS.md) owns per-registry submission
records, and [WIKIDATA_CONTRIBUTION.md](WIKIDATA_CONTRIBUTION.md) owns the staged
Wikidata plan. This file owns the inbound frame and the surfaces neither of them
covers. A fact recorded there is linked from here, not restated.

## 1. The measurement

`make wikidata-inbound` reads the claims of the exact Wikidata items SSTIM maps
and looks for `P2888`, `P1709` or `P1628` values under our namespace. It reports
absence only for items it actually read, which is why absence from it counts as
evidence at all (CLAUDE.md §3.6).

**2026-09-05: 0 of 32. 2026-09-06: 29 of 32.** The first inbound term-level
references SSTIM has ever had were published on 2026-09-06 through
QuickStatements, under the `Rfabbri` account, as two batches generated by `make
wikidata-statements`: the ontology item `Q141325360`, then 29 `P2888` statements
carrying their `P4390` relation qualifier and citing the item, the namespace
document and the retrieval date.

The three items still unlinked are the `relatedMatch` rows held back by design:
`Q863539` binaural beats, `Q17166073` multisensory integration and `Q4826866`
ASMR. See §3 of [WIKIDATA_CONTRIBUTION.md](WIKIDATA_CONTRIBUTION.md) for why.

## 2. Where we can write directly

### 2.1 Wikidata · **done 2026-09-06 for the 29 strong mappings**

The blocker was never the account's standing. `Rfabbri` has edited since 2011 and
carries the conflict-of-interest disclosure required by
[WIKIDATA_CONTRIBUTION.md](WIKIDATA_CONTRIBUTION.md) §5. The blocker is that no
process here holds a credential.

`Special:BotPasswords` on wikidata.org mints a scoped login of the form
`Rfabbri@<name>` plus a generated password, which the MediaWiki Action API
accepts. Edits made with it appear in the account's own contributions. Tick
**Edit existing pages** and **Create, edit, and move pages**; the second is what
creating the ontology item needs. Store it in `docs/credentials/wikidata.md`,
which is gitignored exactly as the BioPortal key is, and never commit it.

**What actually happened.** The QuickStatements route was chosen, so no
credential left this machine: `make wikidata-statements --bare` produced the two
batches and the account owner pasted them on 2026-09-06. Batch 1 created
`Q141325360` in one command; batch 2 applied 87 commands, three per statement
(the claim, its `P4390` qualifier, its reference block), and `make
wikidata-inbound` then read 29 of 32.

The bot-password route stays written down because it is the difference between a
paste per tranche and a submission from here, and later tranches will make that
choice again.

### 2.2 BioPortal, at class level now and concept level after a SKOS record

Measured 2026-09-05, and it corrects an over-broad claim made earlier the same
day. SSTIM **does** have classes in BioPortal: the submission holds 181 of them
and they are indexed, so `search?q=Frequency Band&ontologies=SSTIM` and
`?q=Preset` both return `sstim#` classes. Class-to-class mappings through
`POST /mappings` are therefore possible today.

What limits them is our side, not theirs: the ontology asserts only two
class-level external mappings, both to SNOMED CT, which is licence-gated in
BioPortal. All 68 other mappings sit on SKOS concepts, and under an OWL-format
submission those are ingested as individuals: `?q=Alpha` returns 0 and
`/classes/<techTDCS IRI>` answers 404.

**The SKOS route is now verified, and it was recorded as unverified until this
check.** BioPortal holds **138 SKOS-format submissions** out of 1260. In one of
them, `MARC-LANGUAGES`, a `skos:Concept` (`.../languages/por`) resolves at
`/classes/{iri}`, is returned by search, and carries mappings, even though the
submission's metrics count it among individuals. So a SKOS-format submission of
`sstim-vocab` would make all 551 concepts browsable **and** mappable there.

The open question is not whether it works but whether to run a second BioPortal
record beside the OWL bundle for one artifact. Tracked in `TODO.md`.

### 2.3 BioPortal projects

BioPortal has a `projects` resource, 378 of them today, each declaring the
ontologies it uses, and they surface on the ontology page. A project record for
SSTIM Workbench declaring SSTIM (and the vocabularies it maps) is a second
BioPortal-side reference, writable with the API key already held.

### 2.4 The W3C Community Group homepage

`https://www.w3.org/community/sstim/` is the Sensory Stimulation Vocabulary
Community Group's page on w3.org. Measured 2026-09-05: it mentions the GitHub
repositories and **does not mention `w3id.org/sstim` anywhere**. A w3.org page
linking the namespace is among the highest-authority inbound references
available, it costs one edit, and the group's own chair can make it.

### 2.5 Our own pages · **done 2026-09-06**

The site emitted no `application/ld+json` at all when this file was written, so
no crawler that reads structured data held a record of SSTIM as a dataset.

`src/ui/seo/datasetJsonLd.js` now builds a schema.org `Dataset` node and
`StructuredData.svelte` puts it in the head of `/namespace`, which ADR 0055
makes the HTML branch of `https://w3id.org/sstim`: the one page whose visible
content is the dataset description, which is what the markup is supposed to
accompany. Deliberately not on the entrance, which is about the Workbench.

Two properties make it safe to ship in an artifact other operators self-host.
It describes the **ontology**, not the page, so every IRI in it is persistent:
the w3id namespace as `@id` and `url`, the concept DOI, the ORCID, the canonical
Turtle catalogue. A self-hosted copy therefore contributes to one `@id` instead
of minting a rival record, which is the same reasoning that keeps `og:url` and
`og:image` off the entrance (PORTABLE_DEPLOYMENT §1.6d). And every value is
imported from `releaseMetadata.js`, which `make truth-audit` compares against
`sstim-core.ttl`, `void.ttl` and `CITATION.cff`, so structured data cannot go on
publishing a licence, title, version or distribution the ontology has moved on
from. Four constants were added there for it and are audited the same way.

Verified in the built artifact rather than in the source: `dist/namespace/index.html`
carries the block after `npm run build`, and expanding it against the fetched
schema.org context yields 44 triples about `https://w3id.org/sstim`. Five unit
tests in `datasetJsonLd.test.js` hold the shape, the release identity, the
persistent-IRI rule and the script-safe serialisation.

Still open on this surface: no `sitemap.xml` or `robots.txt` exists, and
Google Dataset Search finds pages by ordinary crawling, so discovery is
unassisted.

### 2.6 ORCID

A works entry on the maintainer's ORCID record for the ontology, identified by
the concept DOI, puts SSTIM in a third-party authority record that many services
harvest. ORCID has an API; the record owner's authorisation is what it needs.

### 2.7 A W3C Community Group report

`w3c.json` already declares this repository's `repo-type` as `cg-report`, and the
group page carries a reports section stating that chairs, when logged in, may
publish draft and final reports. Measured 2026-09-05: the W3C community reports
index does not mention SSTIM.

A published CG report is a document on `w3.org` that cites the namespace and the
terms, under W3C's own publication process rather than ours. Of everything in
this section it is the highest-authority reference available, and the one that
most changes how the work reads to an outside reviewer.

### 2.8 bio.tools

The ELIXIR registry of life-science tools and services. Live, and measured
2026-09-05: a search for `sstim` returns 0 entries. An entry for the Workbench,
with SSTIM as the vocabulary it implements, is self-service registration rather
than a request, which is why it belongs in this section.

### 2.9 Zenodo communities

Zenodo lists 1335 communities matching "ontology". Joining one or more relevant
communities puts the existing deposit on a curated third-party page. Cheap, and
weaker than everything above it, but it is a reference we can create ourselves.

### 2.10 Other OntoPortal instances

BioPortal is one node of the OntoPortal Alliance. The same submission model runs
at AgroPortal, EcoPortal, MatPortal, EarthPortal, IndustryPortal, BiodivPortal,
TechnoPortal, MedPortal and OntoPortal-Astro. Only MedPortal is an obvious
domain fit, and a record in a portal whose community will never look for sensory
stimulation is administrative noise rather than reach. Judge per portal.

## 4. Deliberately not doing

- **Wikipedia articles**, or external links added to existing articles about
  binaural beats and neighbours. Notability requires independent secondary
  sources, and a link added by the project to promote itself is exactly what the
  guidelines exclude.
- **SNOMED CT**, beyond the two identifier references already asserted. The
  licence bars redistributing content, and no inbound path exists that does not.
- **OBO Foundry membership**, declined on identifier policy and reaffirmed on
  measurement.

## 5. The rule this file lives by

Every "not present" in the tables above names the instrument that says so and the
date it said it. An unreachable service is unreachable, never absent. When one of
these lands, replace the row with the verified reference and the date, and re-run
`make wikidata-inbound` for the Wikidata count rather than editing the number by
hand.
