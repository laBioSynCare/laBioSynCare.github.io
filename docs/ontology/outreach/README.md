# Registry and publication correspondence

Messages sent to — or drafted for — the registries, catalogues and platforms
tracked in [`../REGISTRY_SUBMISSIONS.md`](../REGISTRY_SUBMISSIONS.md). One file
per message, named `YYYY-MM-DD-<recipient>-<subject>.md`.

**Why here and not `docs/ecosystem/`.** That directory holds *stakeholder*
outreach — consortium invitations, partner targets, the people side of the
ecosystem. This directory holds *technical* correspondence about publishing the
ontology: registry enquiries, submission follow-ups, upstream bug reports where
the thread matters. The split is by subject, not by formality.

**What belongs here.** Public technical drafts and privacy-safe sent records
whose substance changes what we do. A sent record may state the date, technical
summary and attachment hashes, but it is not a transcript. Record registry
replies in the relevant entry of `REGISTRY_SUBMISSIONS.md`; record other
technical outcomes in the owning ADR or workstream document.

**What does not belong here.** Raw direct messages, headers, mailbox screenshots,
email addresses, contact channels, verbatim responses, consent evidence,
credentials, private ledger data, or unpublished identifiers. These files are
public; access-limited correspondence evidence belongs under the gitignored
`.private/` tree, consistently with ADR 0031.
